# OctoAcme Project Management Docs

This folder holds the project management processes used at OctoAcme. Start here to find the right guide and to get a quick view of how projects run from idea to release.

## Summary of the project management processes

OctoAcme runs cross functional projects through a simple lifecycle: initiation, planning, execution, release, and a closing retrospective. Each project starts with a clear problem statement, stakeholders and a high level timeline, then moves into planning where scope, milestones, resources and dependencies are agreed. Work is delivered in small, testable increments so the team can learn from customers and adjust quickly.

Roles are clearly owned. The Project Manager coordinates delivery, schedules, risks and communication. The Product Manager defines outcomes, prioritizes the backlog and measures success. Developers build and test features and help shape the design, while QA validates quality against acceptance criteria and stakeholders give input and approvals.

Communication follows a steady rhythm: a weekly sync between the Project Manager and Product Manager, regular standups for the delivery team, and status updates to stakeholders. Risks are tracked in a risk register with owners and mitigations, and issues are escalated early.

Quality is built into every step through acceptance criteria, a shared Definition of Done, code review, testing and release checks. After each release the team holds a retrospective, records what worked and what to improve, and turns the lessons into concrete action items.
